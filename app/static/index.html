Disco Diffusion Nano

        
Disco Diffusion for 8GB GPUs, as a local app. Free and open source. 

        

          GitHub
          neuromind.art
          Ko-fi
        

      

    

    
Prompts

    
Write one prompt per line, and all of them guide the image together. End a line with a weight to change how much it counts: :2 counts double, and :-1 steers away from it.

    
Looks

    
A look sets how the prompt shapes the picture, at any size. Changing one of its settings by hand shows Custom.

    

    
Cutouts and schedules

    

    

    
Settings that change over the render are schedules. Each one shows as a graph from the start of the render on the left to the end on the right, with its values in the corner. Click a graph to open its editor. Drag a level up or down to change it, and drag the line between two levels to move the change. Double-click a level to split it there, and double-click a line to join its two sides. The text box takes the same schedule as text, such as [12]*400+[4]*600: 12 for the first 400 of 1000 parts, then 4. A value that differs from the default shows in the accent color. Hover over a setting's name to read what it does.

    
Guidance holds how the push toward the prompt is smoothed and limited, and how the picture is sampled. More settings, at the bottom of some cards, holds the rest of that card's settings.

    
Seeds and Exact repeat

    
Seed 0 picks a new random seed for every render. Any other number starts from the same noise each time; slide it, or type any number up to 4294967295. A seed sets the starting noise, but the GPU adds tiny differences, so the same seed normally gives a similar start and a different image. Exact repeat removes those differences on this PC, at about 30% more time per step. Each image in a run has its own seed, so Reuse settings can make any of them again.

    
Images

    
Right-click the large image or any thumbnail to open it full size, copy it, save it, use it as a start image, reuse its settings, upscale it, or open its folder.

    
Start images

    
Drop an image on the box under the prompt, or click it to choose one. Sizing decides how the image meets the frame. Match sets the frame to the image's shape, at about the same size. Fit keeps the whole image and fills spare space with a blurred copy of it. Fill stretches the image to the frame. Crop fills the frame without stretching and cuts off what doesn't fit.

    

    

    
Memory and CPU

    
CPU threads in All settings limits how much of the CPU a render uses. More threads rarely make it faster, and the default of 4 keeps the PC responsive. Renders also run at below normal priority, so the desktop comes first.

    
The bars at the bottom read the same way. Gray on the left is what the rest of the PC uses. Color on the right of it is Disco: green on VRAM, blue on RAM, purple for its files on the disk. Before a render, the colored part is lighter and shows what the next render will take, so it grows as you add to it. While a render runs, it turns solid and shows what Disco really uses. Hover any part to see its size.

    
The striped end of VRAM is kept free so Windows can draw the screen. When a render won't fit in what is left, part of its working data moves to system RAM by itself, which is slower but works: that part leaves the green VRAM bar and shows green inside the RAM bar. Red means it's too big even then, so lower the size or use fewer prompt checkers. The secondary model is faster and lighter, at lower quality.

    
Guide images

    
Each box takes an image dropped on it, or click it to choose one. A ghost image guides the layout and a style image the texture and palette; their strengths are under Experimental in All settings.

    
Image prompts take many images at once: drop a set of images or a whole folder. They guide the render beside your text. Every prompt checker reads each image, and what the images have in common counts: a subject, a style, a palette, a mood. It's close to what an embedding does, but nothing is trained, so it takes seconds and works with any set. Ten to fifty images that share one idea work best. Image prompt weight sets how much they count beside a text line weighted 1, and below 0 steers away from them.

    
Tiles

    
Tiles builds a larger image from several renders at the frame size, so it needs no more VRAM than the frame does. Every tile takes each step in turn, and the overlaps are averaged before the next step, so neighbors settle on one image with no joins. Time grows with the number of tiles: 4 tiles take four times as long per step, 16 take sixteen times.

    

    

    
Animation

    
Animation renders a clip one frame at a time. 2D moves a flat picture each frame. 3D flies a camera through the scene, with Depth Anything telling near from far, so 3D needs it from Models. Video Input repaints each frame of a video you drop on its box. Every frame after the first starts from the last one, and Frame skip % sets how much of it is kept. Higher is steadier and faster. 75 holds a scene while the camera moves, and 60 lets it keep reinventing itself. Video Input switches to 55, so the video gets repainted more. Frame skip keyframes in All settings can lower it around a prompt change, so the new prompt takes over sooner.

    
For calmer, more painterly clips, try Step noise at about 0.3 under Sampling in All settings. It changes the first frame too.

    
Each move has a slider for a steady value, and keyframes for change over time: 0:(1.0), 60:(1.04), 120:(1.0) eases in and out over 120 frames. Formulas of the frame t work too: 0:(1+0.02*sin(t/8)) sways. The curve button opens an editor: drag a point to change it, double-click empty space to add a keyframe, and double-click a point to remove it. Formulas typed in its text box show as hollow points that can't be dragged.

    
The prompt box is the prompt at the first frame. Change the prompt at a frame adds another box with the frame it starts at, so a clip can travel from one idea to the next. Prompt fade in All settings blends one into the next.

    
Hold colors keeps the light and color close to the first frame's, so long clips don't drift. Turbo repaints only every few frames and lets the camera move the frames between, which is much faster. Last frame as ghost lets Depth target and the ghost's light and dark hold each frame to the last, which is steadier. For Video Input, Blend last frame mixes the last finished frame into each new one, so the painting builds up over the clip, and it follows the video's own motion, so the paint moves with what moves. The first frame gets a first pass of its own, so the clip doesn't open on the plain video.

    
Each clip is saved as PNG frames in a folder, an MP4 and an animated WebP, with a GIF if you choose. Stopping a clip still saves the video of the frames it has. The last frame shows in Images, and clicking it plays the clip.

    
Handoff

    
Handoff brings in a Stable Diffusion checkpoint you already have, SD 1.5 or SDXL, in one of two ways, or both.

    
Checkpoint first, then Disco. The checkpoint paints the start of every image or frame, and Disco carries on. It's not a start image: the checkpoint takes its share of the steps from noise, and Disco picks up while the scene is still blurry. The layout and subject come from the checkpoint, and the paint and detail from Disco. Handoff % is the checkpoint's share: 0 turns this part off, about 30% keeps Disco's look on a sturdier layout, and 50% keeps more of the checkpoint. Disco denoise % works like Denoise for Disco afterwards: 0 carries on from exactly where the checkpoint stopped, and higher has Disco repaint more of it. Handoff 60% with Disco denoise 75% gives Disco 150 of 200 steps on the checkpoint's picture. With a start image or in animation, the checkpoint takes its share of what would be repainted, so every frame of a clip gets it.

    
Reverse handoff: Disco first, then the checkpoint. Disco paints the whole image, and then the checkpoint repaints part of it, like Denoise in img2img. Reverse handoff % is how much: 0 is off, 20 to 35% tidies details such as faces and edges and keeps Disco's look, and 100% replaces Disco's image. It works with Handoff % at 0, for still images only. Keep the handoff picture also saves Disco's own image beside the result.

    
The checkpoint waits in RAM and comes to the GPU only for its own steps. SD 1.5 fits beside Disco. SDXL is stored in 8 bits on cards under 12GB, which halves its memory, and takes a minute or two to load the first time; after that it stays loaded between renders. Handoff steps, prompt strength, the negative prompt and few-step models such as Lightning are under More settings in the Handoff card.

    
The Handoff list shows the SD 1.5 and SDXL checkpoints in your checkpoint folders and in ComfyUI or a Stable Diffusion web UI on the PC that renders, grouped by subfolder. Browse picks a file anywhere on the PC that renders and adds its folder.

    
Experiments

    
These change how the image forms. They're new, so results vary a lot from seed to seed, and they can't run with tiles, symmetry, plms or the secondary model. Whichever you choose first grays out the other, and hovering a grayed setting says why.

    
Time travel backs up and repeats some steps, so the painter can absorb the prompt's push. Subjects get cleaner, for about 35% more time.

    
Four experiments use a small text model, the partner, beside Disco. Get Tiny SD from Models in All settings, about 900MB.

    
Prompt graft adds the effect of your prompt straight into Disco's own decoder, which normally can't read text. Subjects often come out whole, and Disco's paint and color stay. About 3 is a good start. It adds about 0.6GB of VRAM and works only with the 512x512 model.

    
Live ghost lets the partner guide the picture's broad light and dark, and leaves color and detail to Disco. Sketch first paints a quick sketch before the render and takes it out of memory again, so it needs no extra VRAM during the render. Live keeps repainting during the render.

    
Depth target keeps near and far where the ghost has them. A small depth model reads the ghost once and then checks the render at every step, so it works with Live ghost or a Ghost image. About 1 is a good start, and it pairs well with Sketch first and Prompt graft. It adds about 0.1 to 0.25GB of VRAM and a few seconds. Get Depth Anything from Models in All settings, about 100MB.

    
Two painters shares every step between the two models. The partner owns the broad shapes, and Disco owns detail and finishes alone.

    
Borrowed attention gives Disco the partner's sense of which parts of the picture belong together. Subjects often improve. Borrowed layers sets where: Coarse borrows only the broad layout and keeps Disco's color, All borrows everywhere for a stronger, grayer result, and Coarsest changes the least. It works especially well with Time travel.

    
Five more change the checkers themselves, the CLIP models that compare the picture with your prompt. A checker is as happy with bits of a subject scattered over the canvas as with one whole subject, which is why Disco subjects fall apart. None of these needs the partner, and they can be combined.

    
Coherence critic shows the checkers each view twice, once with its pieces shuffled, and pushes the picture so the shuffled one scores worse. Your prompt then only counts when it comes from how the parts fit together, so subjects hold together and the paint stays. About 0.6 is a good start. It adds about 10% time and 0.8 to 1.2GB of VRAM, less with Coherence views set to Whole-image.

    
Robust checker adds a checker that was trained to resist tiny changes, so its push draws real shapes instead of streaks. It leads for the first third of the render, while the layout forms, then hands over to the usual checkers. Expect whole scenes and steadier subjects, with more muted color. FARE4 B/16 costs almost nothing; the L/14 ones are about 70% slower and bolder. Get them from Models in All settings. Robust checker mode set to Together keeps the usual checkers at full strength all along.

    
One subject finds where each subject sits in the picture and pushes it into one place, so it isn't repeated, and keeps separate subjects apart. Name them in Subjects under More settings, separated by semicolons, such as "a woman; a white horse". Left empty, it uses the first phrase of your prompt. About 1 suits one subject and 2 suits two; higher can lose a face. It needs a ViT checker.

    
Corrector steps add small extra steps early in the render, which let the picture settle at each stage before it moves on. One step gives cleaner faces and steadier layouts for about 50% more time. With Two painters, they also make both models agree, which changes Two painters a lot.

    
Prompt routing scores the subject of your prompt on whole-image views and the rest, its style, on close-ups, so the subject forms once and the paint covers everything. The subject is the first phrase of each line, up to the first comma, or the first line. Its curve applies it for the first half of the render by default; the whole render can turn abstract. It costs nothing.

    
Push momentum goes wilder and more abstract as it rises. Broad shapes first, Subject memory and Shaped prompt strength give smaller changes.

    
Models

    
Setup downloads the main model. The others are optional and grayed out in the Model list until you download them from Models in All settings. All of them were tested at 512×512. The style models use about 2GB less VRAM than the main model and take a little over half the time.

    
Rendering on another PC

    
To render on a PC with a GPU while you work on another, turn on Share this PC under Network in All settings on the PC with the GPU. It shows an address and a code. On the other PC, open the address in any browser, or type it into Render on another PC in Nano's own All settings, and type the code once. That PC then uses Nano as if it sat at the GPU PC, and renders, images and settings all live there. From the other PC, Browse and Add folder show the GPU PC's own drives, so handoff checkpoints, the partner's SD 1.5 file and upscaler folders are picked from what is on the GPU PC. Start images, videos and guide images are dropped onto the page and uploaded. Where images are saved, and opening Explorer, are set on the GPU PC itself. Windows may ask once whether Python can use private networks: choose Allow. A new code signs out every other PC.

    
Folders

    
All settings sets where images are saved and where to look for upscalers and checkpoints. You can download Real-ESRGAN x4plus from Models in All settings, or point Nano at a folder of your own.

    

    
Every setting

    
Setting names in All settings switches every name here between plain and official. Lowest and Highest are the ends of each setting's useful range. Going past them is likely to waste time or fail. Schedule settings give the value for one step, written over a 1000-step run: [12]*400+[4]*600 means 12 for the first 400 and 4 for the last 600.
